## 六、数据与状态

- User：id、email、password_hash、created_at。Session：token_hash、user_id、expires_at；Cookie为HttpOnly、SameSite，退出删除会话。
- Project 保存 `id`、`owner_id`、`title`、`revision`、完整项目 JSON 及时间。ProjectVersion 保存每次已确认写入。Canvas 保存 `project_id`、`scene_id`、完整节点、连接和 `viewport`。
- Asset：id、owner_id、project_id、路径、MIME、字节数、SHA256、真实时长、尺寸、poster及生成来源。文件可读和媒体检查成功后才标记可用。
- ProviderSettings：按owner_id保存加密API Key及业务空间、地区和模型；主密钥在忽略的数据目录中以0600权限持久保存。
- Generation：id、owner_id、project_id、scene_id、source_node_id、clip_id、operation_id、input_json、input_hash、quoted_cents、reserved_cents、actual_cents、status、remote_task_id、asset_id、错误与时间。
- TextProviderSettings 保存平台单例、管理员归属、加密的 DeepSeek Key 和配置版本。通过 `SCENETURN_TEXT_ADMIN_EMAIL` 限定管理账号。
- TextGeneration保存任务种类、所属项目与场景、来源及结果节点、原项目版本、冻结输入、结构化真实结果、请求标识、Token用量、微元成本、状态和采用版本。TextUsageLedger以generation_id唯一，防止重复结算。
- 文本状态为queued、submitting、ready、interrupted、submission_unknown、failed和conflict。提交结果待核实时保留费用预留，停止自动重发；模型输出已经取得时，无论结构是否通过，都保留真实用量与成本。人工编辑引发版本冲突时保留结果，用户核对后显式采用。
- 状态：awaiting_confirmation、queued、submitting、submission_unknown、processing、downloading、ready、failed、query_interrupted。提交前保存submitting；进程中断后存在taskId则查询，缺少taskId则进入submission_unknown，禁止自动重新提交。
- 数据与候选全量保存；媒体结果与采用分别记录。采用检查当前项目版本、绑定场景与片段，保留既有互动、裁切及其他素材引用。

## 七、API契约

统一前缀/api/v1；错误为{"error":{"code":"...","message":"..."}}。未登录401，无权限404，版本或操作冲突409，结构错误422，未配置503。请求及响应均由Pydantic校验。

项目响应类型为 `ProjectEnvelope`，字段包括 `project: SceneTurnProject`、`revision: number` 和 `canvases: CanvasSnapshot[]`。编辑器通过 `project.metadata.serverRevision` 获取保存时使用的服务端版本。项目使用 `schemaVersion: 1`，包含 `graphData.nodes`、`graphData.edges`、`assets` 和 `metadata`。时间线使用 `version: 2`。媒体入口由服务端校验。

GenerationView至少包含id、projectId、sceneId、sourceNodeId、outputNodeId、clipId、status、input、confirmationHash、quotedCents、reservedCents、actualCents、remoteTaskId、assetId、error、createdAt和updatedAt。outputNodeId可为空，已有任务沿用原来源节点及原始确认摘要。生成采用提交任务与轮询状态。

新输入契约保存inputCompositionVersion:1、sourcePrompt原文、prompt实际输入及inputs来源列表。文字入边按原画布顺序展开并去重，Group直接成员按画布节点顺序展开；Config的显式@[node:id]按原顺序组织【文本N】引用。最终提示词非空且不超过20000字符；本阶段被实际采用的图片、音频及视频引用明确返回未支持错误。首帧与首尾帧视频按既定阶段2-3实现。

新报价的主要422错误包括GENERATION_INPUT_EMPTY、GENERATION_INPUT_TOO_LONG、GENERATION_REFERENCE_MISSING、GENERATION_MEDIA_INPUT_UNSUPPORTED和GENERATION_OUTPUT_INVALID。原文与已保存节点不符返回409 GENERATION_INPUT_CHANGED。实际媒体识别包含storageKey及同账号、项目、场景内真实任务关联的Asset，结果节点的显示状态由任务派生，费用确认仍依据持久冻结输入与版本检查。

## 八、输入与模型结果校验

本阶段视频提示词由本人输入。Wan提交与查询响应使用明确结构校验；下载实际视频并用ffprobe读取时长、尺寸和编码，用FFmpeg检查可解码性。生成输出通过文件检查后保存为成功状态。

DeepSeek使用正式chat/completions接口、非思考模式、JSON Output和独立版本提示词。通用剧本输出{text}；摘要、角色、道具与场景输出{text}；分镜情节输出{shots:[{no,text}]}且编号唯一；单镜提示词输出{no,text}。所有结果使用Pydantic校验，禁止截取或伪造模型结果。默认分镜为3个画面，由两段各5秒的视频衔接；本人明确提出数量时遵守并保留完整结构，数量质量问题单独记录。

缓存命中、未命中与输出Token按官方usage校验合计关系。任务保存提交时段、价表版本和微元计算结果；分时价格按北京时间及法定节假日计算。服务端预留使用UTF8字节上界、最大输出Token和高峰费率，验证请求与响应的用量上界。销售价格、支付和额度策略保持独立状态。

文本素材支持txt与md，最大10MiB；检测UTF-8、UTF-16与GB18030编码，严格解码后保存内容与编码元信息，保留原始文件字节。上传检查拒绝错误MIME、二进制伪装和不可解码内容。
