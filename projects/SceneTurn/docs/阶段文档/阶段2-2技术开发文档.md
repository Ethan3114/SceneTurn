## 一、阶段目标

2026-11-14确认的素材交互：素材入口内按岗位展示真实产物，问问AI负责持续对话与产物引用。素材对话单独持久化，冻结每轮引用内容哈希、项目版本和历史上下文；总监按需求制定专业岗位计划。R5工具目录限制在素材制作范围，禁止素材任务修改故事、剪辑时间线及互动按钮。已有手动素材编辑通过同一入口保留。供应商报价保存在服务端，用户界面只核对生成输入并确认提交。

素材新任务冻结native-tools-v4-materials-strict协议与R5目录，使用DeepSeek Flash、官方Beta严格函数参数及服务端完整专业校验。[官方参数约束](https://api-docs.deepseek.com/guides/tool_calls/)作为供应商Schema适配依据。字段修订只支持实际允许的标量、标量数组及来源列表；供应商参数采用明确类型，服务端继续校验字段路径、内容基准、来源和完整产物。原有R1至R4任务沿用其冻结协议及工具目录。只读核对步骤依据真实验证回执完成；上游产物读取权限与选中产物修改权限分别检查。

每个素材岗位的模型历史只包含本步骤真实调用；上下文通过已保存产物和来源交接。连续字段修订以当前版本的read_artifact回执，或同一步骤刚保存且返回完整产物及匹配哈希的patch_artifact回执作为基准，保留严格的修改授权、版本、完整结构和来源校验。

已有专业产物采用字段修订，完整新候选另建节点。素材计划中的verify步骤由执行器实际运行validate_artifacts，核对专业结构、来源、内容哈希、版本与文件后保存检查结果；内容质量由本人评分。实际Flash验证记录位于.intermediate/agent-smoke/84f354fc-6605-4a56-8c81-2569712d2899/：两轮对话、16次真实模型请求及实际服务重启通过，保持同一场景产物节点并修改光线要求，未提交媒体生成请求。

素材执行每次接受一个操作。模型返回多个操作时，保存全部真实调用标识，为各调用返回实际拒绝回执，执行有上限的格式修正。原任务的费用、请求数、授权与项目版本限制继续生效。可恢复状态由服务端检查已结算请求、未执行状态和当前项目版本后给出，界面提供“继续当前任务”。普通文字读取返回plain_text、原文、当前版本及内容哈希；专业结构按原有结构、来源和版本规则读取。画布制作安排显示岗位和制作目标，后台instruction用于执行。

每次素材生成独立展示本轮的新增及修订产物，岗位状态及视频任务同样按本轮筛选。项目旧素材和完整历史持续保存，手动画布可继续操作。新任务的materialContext.scope为current_round，模型仅获得本轮需求、本轮产物和用户明确引用的来源；read_project、retrieve_context、read_artifact执行相同范围检查，其他场景正文及历史创作记忆不自动注入。明确引用的旧产物可作为本轮输入，修改保存后在对应岗位展示。

本轮范围更新后，旧计划中超出该范围的历史对象及衔接要求取消。读取授权外对象会在执行前拒绝，原生读取响应按真实调用标识反馈，并在既定两次修正上限内要求改用授权来源；写入权限继续按原规则检查。节点位置及宽高变化只影响画布展示，来源校验先核对保存版本的完整原始哈希，再比较正文、类型、标题和全部业务元数据，继续阻止内容或来源记录失效。已结算的只读调用可在来源重新校验通过后继续执行，不再次请求模型。

文字模型提交结果待核实时，任务暂停。本人可在“重新尝试当前步骤”中确认可能重复计费、保留原费用预留、沿用任务费用上限，并将请求上限调整为40次。接口绑定真实未知调用、当前项目版本、currentRoundOnly和幂等操作，原调用继续保持submission_unknown。项目版本有变化时，记录原版本及当前版本，后续请求重新读取当前产物，不向模型重放旧版本的操作回执。后续请求预算同时计算已知支出和保留的预留；服务重启继续读取确认记录。普通恢复接口保持未知请求检查，工具结果待核实及供应商用量越界不提供该入口。

本人确认后，可为因请求上限暂停的素材任务增加次数，平台最高60次。extend-limit绑定当前版本、本人确认、原上限、新上限和幂等操作，仅修改次数；费用上限、原请求及预留全部保留。新模型请求冻结实际增加上限的操作标识，机器证明核对实际确认记录。未知请求再次确认重试时沿用已经确认的当前上限。

让用户在同一项目中发起创作任务，Agent读取有效历史、选择职责、调用项目工具并交付可检查结果。用户能查看计划和来源、修改目标、停止后续操作、重新连接并继续任务。人工与Agent共用权限、项目版本及持久任务服务。

平台任务调用使用服务端DeepSeek Flash；逐请求保存实际响应模型、真实usage、冻结请求模型及价格版本和供应商预估成本。本人Codex连接作为独立能力保留。图片与视频生成沿用逐次费用确认。已有Pro任务的冻结模型、原始回复及费用继续保留，恢复旧任务时新增供应商请求同样执行模型授权限制。

本阶段交付包括画布中的角色入口、实际场景与素材工具、任务执行与恢复、带分支来源的共享记忆、本机连接与撤销和真实验证证据。总画布负责故事、剪辑、时间线及互动，素材画布负责当前场景的专业创作和媒体候选。图片服务及参考图视频按阶段2-3实现，完整项目导入与独立游戏包按阶段2-4验收。

## 二、技术适配摘要

延续FastAPI、Pydantic、SQLAlchemy、真实SQLite、本地媒体及Next.js界面。复用已有项目版本、生成任务、报价、预算、媒体与文本服务，使用Alembic管理新增数据结构。项目数据在阶段4使用同一repository契约完成真实云端验收。

## 六、数据、资产与状态

每项业务记录保存owner_id、project_id、稳定ID及schema版本。运行记录保存用户目标、授权对象与字段、执行器、角色版本、起始项目版本、限制、状态及停止时间。步骤保存依赖、冻结输入、工具调用、结果、错误、实际用量与完成依据。

工具写入携带expectedRevision和operationId；操作记录与项目变更在同一事务内保存。重复请求返回已有结果，相同operationId携带不同参数时拒绝。模型推理结果保存为候选，成功的实际工具结果决定业务状态。

计划步骤明确kind为produce或verify，dependsOn引用前面的产物步骤。创作步骤需要实际写入；核验步骤由只读validate_artifacts读取前置产物、当前内容SHA256及保存版本，登记可复核的工具证据，再接收模型的完成决策。旧计划与原始调用通过兼容Schema读取，原始JSON、用量和历史保持。

记忆保存来源对象、来源版本、场景、分支、剧情时间、创作时间及有效性。检索包含当前分支及其祖先；互斥分支独有事件不进入当前分支事实。合流处保留条件。候选与失败事件使用各自类型；采用素材建立创作事件及素材引用，剧情内已发生事实由对应剧本版本与分支条件单独记录。修改来源使关联摘要失效，原文和历史完整保留。

运行状态包括queued、running、waiting_confirmation、waiting_connection、conflict、stopping、stopped、completed、failed及submission_unknown；具体步骤状态与运行分别保存。停止后禁止新的工具写入与新生成提交，已提交媒体任务继续记录真实状态。已结算的原始模型回复在重启后继续解析，确定未执行的候选保留为未执行；实际工具结果待核实时保持待核实状态。恢复时重新核对授权、项目版本、租约、原工具结果及原媒体任务，再继续允许的步骤。撤销连接立即阻止新的工具访问。

## 七、接口与工具设计

统一错误结构为`{"error":{"code":"…","message":"…"}}`，响应排除内部异常详情。长任务使用提交、轮询及读取结果；任务接收成功返回202，业务状态从持久记录读取。

所有路径位于/api/v1。身份取自HttpOnly Cookie或受限连接凭据，客户端传入的用户标识不能决定归属。

| 方法与路径 | 请求 | 响应及校验 |
| --- | --- | --- |
| POST /projects/{projectId}/agent-runs | operationId、expectedRevision、goal、targetIds、executor、deliveryMode、limits | runId、status、revision及冻结交付类型；验证权限、版本、能力与费用策略 |
| GET /projects/{projectId}/agent-runs/{runId} | 路径标识 | 计划、角色、步骤、等待原因、结果引用及用量 |
| POST /projects/{projectId}/agent-runs/{runId}/stop | operationId | 停止状态及已提交任务引用；重复请求幂等 |
| POST /projects/{projectId}/agent-runs/{runId}/resume | operationId、expectedRevision | 恢复状态或冲突；重新检查授权与现有结果 |
| POST /projects/{projectId}/agent-runs/{runId}/retry-unknown | operationId、expectedRevision、callId、confirmed=true、maxSteps（最高60）、currentRoundOnly（默认true） | 本人确认后重试文字请求；保留未知调用及预留，幂等返回任务 |
| POST /projects/{projectId}/agent-runs/{runId}/extend-limit | operationId、expectedRevision、confirmed=true、maxSteps（最高60） | 本人确认后增加已达上限的素材任务次数；费用上限保持不变 |
| POST /projects/{projectId}/context/retrieve | sceneId、branchId、目标引用、容量限制 | 片段、来源及版本；检查分支关系和归属 |
| POST /projects/{projectId}/agent-tools/{toolName} | runId、stepId、operationId、expectedRevision、arguments | 结构化result与revision；按角色、任务、字段及工具允许清单执行 |
| POST /projects/{projectId}/connections/pairings | operationId、工具范围及有效期 | 短时配对请求与到期时间；界面明确显示授权范围 |
| POST /connections/pairings/{pairingId}/claim | 配对凭证及连接程序版本 | 受限连接授权；检查一次性使用和过期 |
| GET /projects/{projectId}/connections | 项目标识 | 连接状态、范围与最近活动时间，排除原始凭据 |
| POST /projects/{projectId}/connections/{connectionId}/revoke | operationId | 撤销结果；立即拒绝后续工具调用 |

连接程序主动领取绑定项目的Codex步骤、返回结构化工具请求与结果。领取和回报复用同一runId、stepId及租约；连接授权范围与有效期在每次请求检查。公开浏览器会话不能调用连接程序的任务回报接口。

工具允许清单沿用Harness契约并包含专业交付工具：read_project、retrieve_context、write_script、write_artifact、read_artifact、patch_artifact、apply_canvas_ops、submit_generation、inspect_generation、adopt_asset、validate_scene、validate_artifacts、write_memory、split_image及join_videos。角色分别取得其职责允许的工具。publish_release在发布能力阶段按固定版本及独立人工确认开放。本阶段接入已实现的检查和编辑对象，后续能力通过能力查询明确区分。

媒体请求由submit_generation保存冻结输入并取得报价，用户确认前停留在waiting_confirmation。模型不能产生有效确认、修改报价、改变余额或登记已付款。旧输入确认失效、费用预留与未知提交状态继续使用既有规则。

主要错误包含UNAUTHORIZED、FORBIDDEN、NOT_FOUND、REVISION_CONFLICT、OPERATION_CONFLICT、TOOL_NOT_ALLOWED、TARGET_CHANGED、RUN_STOPPED、CONNECTION_REVOKED、PAIRING_EXPIRED、CAPABILITY_NOT_AVAILABLE、CONFIRMATION_REQUIRED及现有预算与计费错误。参数错误返回422，版本或状态冲突返回409，未登录401，越权403，资源不存在404。

## 八、Prompt与输出约束

每个角色独立保存职责、允许工具、输入变量、输出Schema、完成条件及来源要求。创作总监输出具有依赖和目标引用的计划；编剧、分镜师输出对应结构化产物；其余角色按能力查询安排实际可执行步骤。

专业产物由write_artifact按实际执行角色的Pydantic Schema严格校验，并在同一次项目事务保存完整结构化对象、中文正文、独立生图提示词、契约版本和内容哈希。每个角色、场景或镜头的生图提示词分别保存，包含主体设定、动作互动、环境、构图镜头、风格、光色、细节、避免项和输出规格，可供下游按单个对象引用。原有write_script继续支持明确的局部文字修订。

任务创建时冻结交付类型：professional要求当前岗位实际专业写入回执、当前有效产物与真实来源，支持write_artifact创作及read_artifact后patch_artifact字段修订；text_edit要求受授权已有文字的局部写入；tool_action要求实际业务处理或明确核验工具的结果。专业类型为界面默认值，局部修订要求角色具备文字修订工具及有效文字目标。旧任务沿用其保存的交付规则。

来源校验独立于上下文的文字容量，覆盖项目归属、分支、来源版本及间接依赖。外部来源更新会使相关产物失效；同一目标原文字作为本次修订输入时保存原版本快照。人工修改正文继续保留，产物核验同步检查结构化对象、完整正文、独立提示词及其哈希。
