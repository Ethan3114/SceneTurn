# 前端适配声明

## 1. 项目判断

SceneTurn 互动影像创作平台面向个人创作者。本期桌面浏览器支持注册、登录、剧情编排、素材制作、剪辑、确认、备份和网页游玩。

阶段 2 的工作台已经实际连接项目、素材、生成任务和播放器，会继续用于正式产品。沿用现有布局、深色画布、编辑器导航和媒体控件。素材制作从编辑器的「素材 → 生成素材」进入。此处使用素材对话与岗位成果区，剧情画布、时间线和手动操作沿用编辑器入口。

## 3. 技术选择

- 延续 `frontend/` 中的 Node.js 26.10、npm 11.19、Next.js 16.2.7 App Router、React 19.2.7、TypeScript strict、Tailwind CSS 3 和现有样式。故事图、时间线、素材画布、播放器及国际化继续采用各自现有组件。项目条目、对话、确认卡、状态提示和媒体预览使用一致的间距、焦点和文字样式。
- 工作台使用 `cloudApi.ts`、`agentApi.ts`、`materialApi.ts` 请求同源 `/api/v1`。登录会话由 HttpOnly Cookie 管理，任务、项目、素材及权限以服务端为准。页面本身保留输入草稿、选中项、缩放和展开位置。用 URL 恢复项目、场景或固定版本，用服务端记录恢复对话和任务。
- 复用现有表单组件及 Zod 响应校验。错误统一读 `error.code` 和 `error.message`，等待、空内容、无权限、网络中断和业务失败分别显示。长任务按现有异步提交、轮询与结果查询契约接续，素材对话已有运行中轮询。离开页面后仍可通过原任务记录继续查看。
- 阶段 3-1 与 3-2 使用现有 Vitest、Playwright 及真实登录、后端和媒体。每阶段运行 ESLint、类型检查、测试和生产构建，浏览器实测核心闭环与异常路径。
- 预览沿用本机 Web 3210 与 API 8310。现有 Next.js 使用 standalone 输出和本机同源改写。阶段 3-2 准备前端运行镜像、运行时后端地址和同源代理，核对 Cookie、媒体 Range、上传及代理身份校验。阶段 4 在已确认的云环境部署和验证线上访问。

## 4. Agent 状态

| 服务端状态 | 页面展示与可用操作 |
| --- | --- |
| `queued`、`running` | 显示等待或当前岗位与已保存成果，允许查看历史、切换项目及按任务能力请求停止。 |
| `waiting_confirmation` | 在原对话显示具体问题或成果确认卡。说明确认后的动作，提供补充、修改和适用的确认入口。 |
| `waiting_connection` | 在剧情对话提示连接本人 Codex，连接后从原步骤继续。已提交的供应商任务仍可追踪。 |
| `conflict` | 指明发生变更的项目、场景或片段。读取最新版本后重新核对；保留用户当前编辑。 |
| `stopping`、`stopped` | 区分停止中和已停止，展示已保存成果和已提交任务。按允许范围恢复或手动接管。 |
| `completed`、`failed` | 已完成时给出可查看的成果；失败时说明影响的步骤及可执行操作。已经保存的其他成果继续显示。 |
| `submission_unknown` | 显示提交结果待核实，继续关联原任务。使用专用核对与重试确认，保留原提交和费用记录。 |

每个任务通过项目、场景、对话和任务标识找回。确认绑定当前输入和成果版本，改变输入后重新生成确认卡。提交和确认使用既有操作标识防止重复写入。用户补充要求、询问进度或请求继续时，消息接续当前任务；通过「开始新一轮制作」才开启新的任务。本轮新增与修订成果由岗位区域展示，完整历史可从原对话和项目素材查阅。

## 5. 页面与产物

| 页面或入口 | 工作内容与现有契约 |
| --- | --- |
| 首页、作品馆与作品详情 | 首页播放《潮汐尽头》先导片并提供创作入口。作品馆浏览经过授权的固定版本，详情展示作品信息并进入实际可玩的影院。角色互动作品由创作者制作。发布和撤销权限沿用固定版本规则。 |
| `/account`、`/projects` | 注册、登录、退出、建立并打开工程、导入与恢复、直接网页游玩。使用现有账户、项目和导入记录接口。 |
| `/editor?id=…` 的故事画布和时间线 | 编排场景、裁切媒体、设置按钮和 QTE、连接剧情分支。保留手动操作。剧情「问问 AI」连接本人 Codex，项目版本、冲突及写入检查使用既有项目和 Codex 接口。 |
| 编辑器「素材 → 生成素材」 | 「问问 AI」承接素材需求、必要澄清、岗位进度、采用和改稿。按场景使用 `material-conversations` 的读写、消息和答复接口，岗位画布展示当轮可交付成果。手动画布通过素材入口打开。现有链接继续识别项目和场景。 |
| 素材候选、媒体任务与时间线采用 | 预览真实图片、视频及音频。使用现有媒体任务和连续视频接口，确认后生成或选定候选；替换只作用于指定片段，保留裁切、按钮、QTE 和分支。实际时长冲突需解决后再发布。 |
| 生成设置、用量与开发记录 | 复用现有文字和视频设置及受权限约束的开发记录。普通对话只展示用户原话、制作简报、状态、确认问题和可交付成果。模型提示词、工具 JSON、供应商价格及用量由获授权入口读取。 |
| 编辑器「试玩」、`/play/[id]` 和固定版本 | 用同一个播放器运行场景、按钮、QTE 与分支。项目备份、固定版本确认与下载沿用 `transfers` 接口。网页播放是默认交付入口，游戏包可选下载。公开范围随固定版本确认，线上权限与撤销在阶段 4 验证。 |

正式制作的核验过程从同一个新项目开始。创作者在故事画布确定开头、选择点和各线路，可以用本人 Codex 协助编排。总编在素材对话厘清拍摄需求并派工，编剧按已确定的剧情扩写成可拍摄的完整剧本。角色和场景设计读取已采用的剧本，分别产出角色图与场景图。分镜师参照剧本、角色图和场景图，按每场戏的动作节拍拆镜和标定时长，逐镜头准备有序边界图。各岗位引用自己实际读取的上游版本。

每条连续链路的 n 段视频绑定 n+1 张边界图，相邻两段共用同一张实际图片；分支起点沿用经采用的分岔画面。逐段准备视频，视频师同时收到该段剧本、动作、运镜、声音要求及实际首尾图。确认卡展示镜头内容、首尾帧和规格，视频由创作者逐项确认后提交。既定图片模型、串行队列和步骤间隔沿用决策台账。采用视频后，由本人 Codex 或手动编辑完成时间线、按钮、QTE 和分支。试玩需走过共用开头、选择点及两条后续线路。

桌面以 1440 像素绘制全部界面，用 1280 像素原型检查窄窗口的画布和工具栏。现有深色画布沿用项目设计，工具栏按导航、当前任务和主要操作分组。左侧导航保留明确选中态，右侧属性和对话按需显示。可恢复错误、运行状态和长任务进度在原位置呈现。视频提交、发布和不可撤销删除提供带明确动作和取消入口的确认。

阶段 3-1 与 3-2 在 1280 和 1440 像素宽度的桌面浏览器验收。检查键盘和指针操作、焦点顺序及恢复、文本和状态对比度、界面缩放、媒体播放、长任务恢复、读屏名称和返回路径。画布编辑响应沿用 PRD 的 P95 不超过 200 毫秒指标。具体设计原则与 Apple 官方来源随 Figma 原型说明保存。

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 3-0 | 确定桌面范围，完成 Figma 静态页面。作品首映、作品馆和影院采用电影视觉，工作台控件遵循 Apple HIG。 | 在 Figma 核对作品呈现、剧情编辑、素材制作、任务状态与交付界面。 |
| 3-1 | 在现有工作台完善正式页面，贯通完整剧本、有序分镜、逐段视频、素材采用和互动。 | 从同一完整剧本制作实际可玩片段，在网页走通两条线路。核对中间确认、岗位成果、片段替换与手动接管。 |
| 3-2 | 完善桌面窗口、键盘与指针、媒体和任务恢复、备份导出、发布准备。 | 在两种桌面宽度实测任务和作品，检查实际媒体、保存冲突、访问隔离、播放和导出，并对真实作品内容评分。 |

## 6. 偏离本手册的地方

前端子阶段按技术适配声明归并。阶段 2 已有可运行工作台，手册中的可运行骨架、首条真实闭环和 Agent 完整交互归入 3-1；质量与发布准备归入 3-2。

第 21.5 节将页面和模型实测写为每个前端子阶段的要求。项目规则卡将 3-0 定义为文档阶段，页面和模型实测用于 3-1、3-2。第 21.5 节和第 24 节的模拟数据条款在本项目以实际接口、任务及媒体证据执行。建议通用模板明确标记文档阶段、项目已有规则及真实验证的适用范围。

手册第 16、21 节的终端宽度按本期桌面范围取 1280 和 1440 像素。Apple HIG 的 macOS 交互原则用于桌面网页，浏览器保留自身的窗口控件和系统快捷键。
